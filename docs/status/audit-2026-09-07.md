# Platform Audit — 2026-09-07

Baseline revision: `dff388f` (master). This audit is the evidence record for
task R0.1; the task ledger is [`platform-status.yaml`](platform-status.yaml)
and scope/acceptance live in [`../../ROADMAP.md`](../../ROADMAP.md).

## Method and limits

Selected source tests and selected backend tests were run from the existing
workspace; no fresh clean build was performed. Results are observations of the
audited revision on one development host (Ubuntu 22.04, ROS 2 Humble, arm64
target). Historical startup reports from earlier phases were treated as
unverified claims, not evidence.

- `full_suite: false`. These numbers do not constitute mission qualification.

## Confirmed defects and verification limits

- **Installed entry points / portable paths (R1.1):** benchmark executable ROS
  placement is wrong; advertised executables/plugins/launch files were not all
  verified against the installed index.
- **Test tiers (R1.2):** numerical, ROS-node, launch-contract, physics, mission
  and hardware tests are not separated; one DeadReckoning initialization failure;
  some qualification tests count documents rather than verifying behavior.
- **PyBullet / MuJoCo:** headless physics/import tests pass; ROS clock, data and
  control integration needs repair.
- **Isaac Sim:** runtime subprocess code exists; full startup/mission unverified
  in this audit; no scan/RGB-D publishers; clock contract needs repair.
- **Gazebo:** primary configured path; only historical startup reports available.
- **GUI:** end-to-end operation was not exercised by this audit.
- **CI/bootstrap/doctor (R1.3):** required-test failures ignored, invalid test
  paths referenced, build/dependency failures can pass.

## Explicit exclusions at this revision

Fresh clean build; full simulator missions; GUI end-to-end operation; Isaac
startup; physical hardware; all robot/backend combinations; five live
comparisons per algorithm category.

## Consequences

- Catalog maturity labels were left unchanged; they overstate runtime support.
  R3.1 reconciles metadata and its tests together.
- Claims from historical narrative (e.g. green test counts, host-specific
  install logs) must not be copied into current support claims. The pre-audit
  narrative remains available via `git show dff388f:ROADMAP.md`.
- Next work: R0.2 (publish truthful docs + this handoff protocol), then R1.1
  and R1.2 in parallel (see ledger `next_task`).
